## How it runs

- Install `npx -y pnpm@10.4.1 install`; dev `npx pnpm@10.4.1 dev` → http://localhost:4317 (bound to 127.0.0.1).
- Tests `./node_modules/.bin/vitest run` (145 passing on this branch), types `./node_modules/.bin/tsc --noEmit` (clean).
- The port is fixed: if 4317 (or `PORT`) is taken, the server now stops with an explanation instead of moving to another port the mod and hooks can't find.

## What works today (verified)

- Detects running Claude Code sessions from `~/.claude` transcripts and the session registry; status working / needs approval / asked a question / your turn / idle / finished / error, with the current action as text.
- Optional HTTP hooks (installed only via Settings, with preview and backup) for exact permission alerts.
- With the mod: send a message, stop, approve/deny permission requests, answer Claude's questions, all from the browser; falls back to the terminal after 45 s.
- Chat drawer with the conversation, tool steps (labels only), inline requests; toasts and sound cues; "needs you" rail.
- Two places (Kerala, Bengaluru on #5), three characters (per-project choice), six art styles + Style lab, subagent companions.
- Packs: hot reload, validation, .zip upload with backups.

## Known issues (not fixed in Phase 0)

1. **Skills & agents editor writes into `~/.claude`** (`server/routers/agents.ts`: `SKILL.md` and agent files under `~/.claude/skills|agents` and projects' `.claude/`), on the person's save. CLAUDE.md says the app never writes inside `~/.claude` except hook entries. Needs a decision: keep (document as an explicit exception), make read-only, or remove.
2. **Tool output isn't shown** in the chat, only one-line tool labels, although the transcripts hold the real results.
3. **No project list, filters or search** beyond the Sessions dock; buildings in the world aren't clickable.
4. **No history** of past sessions in the UI (transcripts exist on disk).
5. **No clear "no recent activity" state**; only a soft "may be waiting for approval" hint without hooks.
6. **Status colours are defined three times** with different values (`client/src/lib/status.ts` STATUS_META, `client/src/styles/live/types.ts` LIVE_STATUS_COLOR, `client/src/styles/scene.ts` STATUS_COLOR for the Style lab).
7. **On machines where another plugin answers `PermissionRequest` first**, permission prompts stay in the terminal (questions still come to the browser).
8. Pack `sounds`, `lines` and the world `completion.sound` are validated but never played or shown; the `vehicle-pass` and `bell` effects have no visuals of their own; the Phaser world assumes ~1080 px tall worlds (see docs/WORLDS.md).
9. Leftovers from the starter project: a remote bridge using an old data format (`bridge/`, `server/websocket.ts` bridge section) and unused npm packages / UI-kit components. Not removed: they need a decision, not a cleanup.
